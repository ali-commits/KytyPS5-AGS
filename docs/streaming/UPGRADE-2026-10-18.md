# Native streaming upstream upgrade

This upgrade combines the newer settings interface and upstream fixes with the
complete native streaming branch at `58fd5fee`.

The settings retain master, game, music, PC controller-speaker and 3D-object
volumes, the 3D-object toggle, accurate occlusion, physical controller settings,
cheat import/selection and the Streaming tab. Shared argument construction keeps
local and streamed launches consistent. The added HDR, performance, keyboard,
native-module and additional-content controls remain available.

The integration also fixes depth-state initialization, shader planning lifetime,
remote gyro ownership, performance counters and native-module callback reentry.
Existing streaming capture, private audio, phone/TV coordination, controller audio,
cheat safety checks and U59 shader behavior are retained.

## Installation and data

The versioned package is installed under
`~/.local/opt/kytyps5-streaming/20261018-upstream`, with its private profile under
`~/.config/kytyps5-streaming/20261018-upstream`. The `kytyps5-streaming` command opens
this launcher. The Phone + TV host desktop entry uses the matching package.

Saves and runtime caches are independent copies of the latest v4 runtime. Launcher
preferences come from the current default installation. The complete v4 streaming
certificate, host identity, authentication, pairings and companion preferences are
migrated together. Existing phone and TV applications keep their identities; this
upgrade does not install applications or modify devices.

`installation-provenance.json` records the native, launcher and pinned backend
revisions and hashes. `verification/upgrade` contains the installed verification
record. The existing v2, v3 and v4 installations remain available for rollback.

## Rollback

Stop `kyty-three-apps-20261018.service` before starting the old host. Restore the
backed-up `kytyps5-streaming` command and Phone + TV desktop entry from the new
package's `rollback` directory, then use the old v4 `start-host.sh` if needed.
Only one host can use the preserved streaming identity and port at a time.
New saves are independent; rollback does not automatically copy them backward.

Automated protocol/GPU tests and a bounded game smoke do not replace fresh physical
acceptance of HDR, 4K, native haptics or adaptive triggers on the user's devices.
